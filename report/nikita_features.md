# Признаки Никиты для сегментации буровых операций

Источник — `data/clean_data.parquet`. Скрипт `src/features.py` сохраняет исходные 12 столбцов и добавляет расчётные признаки: 10 в `data/features_v1.parquet` и ещё 2 в `data/features_v2.parquet`. В обеих таблицах 180 901 строк; скрипт проверяет совпадение количества и порядка `ID` после записи.

Обозначения: `Δx = x[i] − x[i−1]`, `Δt = Time[i] − Time[i−1]` в секундах. Для производных при `Δt ≤ 0` получается пропуск. Знак скорости означает направление изменения **показания датчика**; физическое направление движения нужно сверять с устройством датчика.

| Признак | Как считается | Что помогает увидеть |
|---|---|---|
| `block_speed` | `ΔTravelingBlockPosition / Δt` | Движение талевого блока и его направление. |
| `flow_on` | `1`, если `InletFlow > 0`; иначе `0` | Подаётся ли буровой раствор. Пропуск исходного потока сохраняется. |
| `rotor_speed_abs` | `abs(Turn_rotor)` | Силу вращения независимо от знака показания. |
| `bit_speed` | `ΔBitPosition / Δt` | Изменение положения долота и его направление. |
| `flow_state_seconds` | Время от начала текущей серии одинаковых `flow_on` | Как давно поток включён или выключен. |
| `depth_rate` | `ΔDepth / Δt` | Растёт ли измеренная глубина; помогает отличать бурение от работы без углубления. |
| `flow_rate_change` | `ΔInletFlow / Δt` | Момент увеличения или уменьшения подачи раствора. |
| `pressure_rate` | `ΔManifoldPressure / Δt` | Быстрое изменение давления в манифольде. |
| `hook_load_rate` | `ΔHL / Δt` | Быстрое изменение веса на крюке. |
| `block_range_30s` | Максимум минус минимум `TravelingBlockPosition` за последние 30 секунд | Движение блока, даже если он вернулся в исходную точку. |
| `flow_median_30s` | Медиана `InletFlow` за последние 30 секунд | Обычный уровень потока на коротком участке, устойчивый к одиночному скачку. Только v2. |
| `flow_deviation_30s` | `InletFlow − flow_median_30s` | Насколько текущий поток отличается от недавнего уровня. Только v2. |

Окна 30 секунд включают текущий замер и не заглядывают в будущие строки. Для окон нужно хотя бы два наблюдения; иначе значение пустое. Производные считаются по соседним строкам даже через большие временные разрывы: это ограничение v1/v2, а не подтверждённая скорость во время отсутствия замеров. При обучении модели такие места нужно обрабатывать отдельно.

В ноутбуке Юли v15 из `features_v1.parquet` фактически подгружен `block_range_30s`; остальные её признаки рассчитаны в ноутбуке. Влияние каждого нашего признака на официальный Score по отдельности не измерялось. Наличие признака в таблице само по себе не означает, что итоговая модель его использует.

## Как получить таблицу

Из корня репозитория в PowerShell:

```powershell
python -m pip install pandas pyarrow
python .\src\features.py --version v1
python .\src\features.py --version v2
```

Для просмотра нескольких строк без Excel:

```powershell
python -c "import pandas as pd; print(pd.read_parquet('data/features_v2.parquet').head().to_string(index=False))"
```

`src/physical_model.py` — отдельная пробная модель, которая учится на CSV с метками Юли. Её внутреннее совпадение с этими метками не является официальным Score и не проверяет правильность технологических названий классов. Подробности — в `report/physical_model_2026-11-27.md`.
