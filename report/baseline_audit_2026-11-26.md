# Проверка первого решения и поиск интервалов для разметки

26 ноября. На 226 интервалах без потока и с малыми оборотами показание клиньев почти полностью разделяет два наблюдаемых типа движения. Это кандидаты для ручной проверки и обучения модели на правилах. Технологические названия операций ещё предстоит установить.

## Что известно о первом решении

В приложенном `submission_baseline.csv` два поля, `ID,class`. Все 180 901 идентификатор уникальны и совпадают с исходными в том же порядке. Встречаются все девять целых меток от 0 до 8, пропусков нет. Получен и проверен файл `submission_baseline (1).csv` с полями `ID,operation`: все ID и все метки в том же порядке полностью совпадают с предыдущим CSV. Отличается только заголовок второго столбца. Связь отправленной разметки со скором 0,343554 указана со слов команды.

Сравнение с файлами коммита `ddd0085`. Массивы NPY сопоставлены с CSV по позиции строки. ARI здесь измеряет сходство с CSV капитана при произвольной нумерации классов. Эталонные ответы неизвестны.

| Разметка | ARI с CSV | Смены класса | Возвраты A → B → A за один замер |
|---|---:|---:|---:|
| CSV капитана | 1 | 3 568 | 140 |
| Голосование Дани | 0,7551 | 2 506 | 162 |
| GMM, seed 0 | 0,7852 | 2 269 | 130 |
| GMM, seed 21 | 0,7707 | 2 433 | 152 |
| GMM, seed 123 | 0,8179 | 2 601 | 159 |
| K-Means Robust | 0,4511 | 3 059 | 235 |
| Agglomerative Quantile | 0,3750 | 940 | 0 |

Ни один из шести массивов не воспроизводит разбиение CSV в точности. У Дани меньше смен класса в целом, но больше одиночных возвратов. Эти счётчики сами по себе не определяют лучший результат для лидерборда.

## Какие интервалы отобраны

Во всех замерах интервала поток равен нулю, модуль показания ротора меньше 1. Размах каждого положения — максимум минус минимум за последние 30 секунд. После разрыва более 10 секунд окно начинается заново. Требуются два показания в окне и не менее 120 секунд непрерывного выполнения условия. В обоих типах размах блока больше 0,5. Для первого типа размах долота меньше 0,05, для второго больше 0,5. Второй тип означает движение обоих в окне, независимо от направления. Датчики клиньев и нагрузки в правила отбора не входят.

| Тип | Интервалы | Замеры | Дни начала | Медианное показание клиньев выше 0,5 | Типичное HL* |
|---|---:|---:|---:|---:|---:|
| Блок движется, долото почти неподвижно | 19 | 1 456 | 6 | 0 из 19 | 11,31 |
| Движутся и блок, и долото | 207 | 12 217 | 7 | 206 из 207 | 68,59 |

\* Медиана по каждому интервалу, затем медиана по интервалам. Длинные серии получают тот же вес, что и короткие. Пороги исследовательские и получены на этом наборе. Из показания клиньев пока нельзя уверенно вывести «открыты» или «закрыты». При увеличении обоих порогов движения с 0,5 до 1 остаются 15 и 99 интервалов соответственно; различие в типичных показаниях клиньев и HL сохраняется.

## Где смотреть и что проверять

- ID **13365–13644**. Блок прошёл диапазон 43,25 единицы при постоянном показании долота. Медиана клиньев −0,63. Самая частая метка у капитана 6, у Дани 0. Номера относятся к разным моделям.
- ID **24365–24524**. У блока и долота одинаковый размах 20,61, медиана клиньев 1,10. В большинстве строк капитан даёт класс 4, Даня — 7.
- В группе с движением обоих датчиков у капитана 11 752 из 12 217 строк уже получили один класс. Поэтому наиболее полезны для разбора исключения и границы, где начинается и заканчивается движение.

[Все 226 интервалов с ID, длительностью и показаниями](motion_intervals.csv). Следующая проверка — отложить целые дни, подобрать правило по остальным дням и посмотреть на отложенных примерах, где оно ошибается. Даже хорошее распознавание этих двух типов движения не заменяет оценку девяти классов.

Воспроизведение из корня репозитория: `python report/audit_baseline.py "путь/к/submission_baseline.csv"`. Нужны pandas, pyarrow, numpy, scikit-learn и локальный git-коммит `ddd0085`. Скрипт обновляет каталог интервалов.

## Проверка исключения и границ

Единственное исключение с движением обоих датчиков и медианой `WedgePosition ≤ 0,5` — ID **99917–99946**. Показания блока и долота здесь идут почти параллельно. На ID 99917 клинья показывают около −0,04, а около ID 99941 переходят к 1,00. Поэтому медиана за весь 145-секундный интервал скрывает смену состояния внутри него. Медиана `HL` за интервал — 91,02.

На ID **24365–24524** состояние клиньев сменилось ещё за один замер до начала отобранного движения. На ID **100047–100201** оно вернулось к значению около нуля к концу отобранного интервала. Напротив, на ID **13365–13644** долото всё время стояло, хотя блок двигался, а показание клиньев оставалось около −0,63. Эти три примера подтверждают, что граница интервала, найденного по размаху за 30 секунд, может запаздывать за переключением датчика или оставаться после остановки движения. Такие границы нельзя напрямую считать границами технологической операции.

Практический вывод: `WedgePosition` следует использовать как отдельный сигнал о состоянии, а не как готовую метку операции для всего интервала. До обучения модели на правилах стоит проверить пороги и моменты переключения на отложенных днях. Данные и разметка остаются без эталонных классов, поэтому эффект на официальный score пока неизвестен.

## Проверка по дням

Для каждого дня я отдельно подбирал порог медианы `WedgePosition` по интервалам всех остальных дней, затем применял его к отложенному дню. При равной точности порог выбирался ближайшим к 0,5. Получилось **225 из 226** верно разделённых интервалов по уже заданным выше типам движения. Единственное расхождение снова ID **99917–99946**, где клинья переключились внутри интервала.

Проверка подтверждает устойчивую связь датчика клиньев с этими типами движения, но не точность классификации всех замеров и не качество девяти классов.

## Первая обучаемая проверка

Логистическая регрессия обучена на медианах датчиков по интервалу. Каждый день по очереди исключён из обучения и использован для проверки. Для обоих типов движения результаты такие:

| Входы модели | Верно разделено |
|---|---:|
| Только показание клиньев | 225 из 226 |
| Только `HL` | 223 из 226 |
| Клинья и `HL` | 226 из 226 |

Совместная модель разобрала переходный интервал ID **99917–99946**, где клинья поменяли состояние внутри движения, а нагрузка была высокой. Код проверки — `src/check_anchor_model.py`. Это классификатор **двух заранее отобранных типов интервалов**. Для всех 180 901 строк и девяти технологических классов качество этой модели ещё не измерено. Примеры сильно неравномерны по дням и типам, поэтому результат следует проверить на новых данных, прежде чем использовать для отправки.
